## Pipeline and justified decisions

1. **Anchor features:** manually crop each whole target; cap its longest side
   at 960 px; grayscale SIFT and normalized 16 hue x 4 saturation histograms.
2. **Candidate generation:** RGB frame capped at 960 px; red HSV mask
   (`H<0.065 or H>0.94`, `S>0.45`, `V>0.12`), radius-2 closing, minimum 20-pixel
   components. Keep red regions at least 8 px high, with height/width in
   [1.2,15]. Expand sideways/upwards to include the hose; at most 20 proposals,
   prioritized by red component area. These object-specific constants are
   starting design choices, **not empirically optimized results**.
3. **Baseline:** compare each proposal histogram to every anchor with
   `sum(sqrt(anchor .* candidate))`. Rank by the maximum coefficient, output
   the best proposal box if its validation-calibrated threshold is met.
4. **Final:** resize each proposal's longest side to 480 px; SIFT unique
   matching, ratio 0.75. Estimate a projective transform per region-anchor pair
   with RANSAC (2,000 trials, 99% confidence, 4 px residual in candidate
   coordinates). Require >=6 inliers, >=0.35 inlier ratio and >=0.02 anchor
   coverage (bounding span of inliers / anchor area). Reject nonfinite,
   nonconvex, implausibly large/small or badly placed projections.
5. **Evidence:** `inliers * inlierRatio * sqrt(coverage)`. Rank valid pairs
   before invalid ones, then descending score. Invalid geometric hypotheses
   are logged with a reason. A frame with no valid hypothesis is absent even
   when threshold=0. Keep best candidate center even below threshold to allow
   honest calibration without rerunning localization.
6. **Localization:** project cropped-anchor corners; enclose by an
   axis-aligned box. Pixel-center-aware scaling returns original coordinates.
   Baseline and final thresholds are separate because their score scales differ.
7. **Calibration:** test unique valid validation scores plus 0 and reject-all
   (`Inf`); best F1 among thresholds meeting precision >=0.75 and recall >=0.60.
   Ties prefer precision, then the higher threshold. If none meet both, emit a
   warning, choose best F1, and record `ValidationTargetsMet=false`.
   Evaluation never selects parameters. An infinite threshold appears as
   `null` in JSON and is displayed as reject-all by the report builder.

The candidate generator is deliberately simple and target-specific. Both
systems can miss red-poor/occluded views before matching. SIFT and a homography
**cannot prove physical authenticity**: a printed copy can preserve excellent
features and geometry. Nonplanarity of the actual extinguisher also violates
the single-homography approximation. Depth or temporal parallax are future
experiments, not implemented capabilities.

## Metrics

`evaluateDetection` aligns exact, unique frame IDs rather than assuming row
order. Reference labels must be reviewed, finite and valid.

- Correct localization: predicted box center inside reference box, inclusive
  edges, exactly as required; not an IoU criterion.
- TP: accepted and correctly localized real target.
- FP: **any** acceptance that is not a TP (replica, distractor, background or
  mislocalized positive).
- FN: any present real target without a correctly localized acceptance.
- Therefore a mislocalized acceptance is **both FP and FN**; do not expect
  TP+FP+FN+TN to equal the number of frames.
- Precision = TP / all acceptances; recall = TP / real-target frames.
- Localization success = correct accepted localizations / **all accepted
  detections**, reported as number and percentage. It equals precision for
  this one-acceptance-per-frame protocol.
- Empty denominators use 0 numerically and an explicit `*Defined=false` flag,
  never an artificial perfect score.
- Proposal-center recall is a separate diagnostic: fraction of positive
  evaluation frames with any proposal center inside the reference. It is not
  final-method recall or a guarantee that projected boxes will be correct.
- Runtime includes matching and shared proposal generation, not image I/O or
  one-time anchor setup. It is an offline measurement, not a real-time claim.

## Outputs and presentation evidence

`results` contains:

- `summary.json`: counts, scores, targets-met flags, runtime and anchor usage.
- `{baseline,final}_predictions.csv`: every frame's best score, validity,
  thresholded acceptance, anchor, original-coordinate box/center and seconds.
- `{baseline,final}_candidates.csv`: ranked evidence for every proposal/pair;
  bbox matrix columns expand into MATLAB CSV columns.
- `{baseline,final}_thresholds.csv`: **validation** sweeps.
- `{baseline,final}_outcomes.csv`: **evaluation** TP/FP/FN/TN/localization flags.
- `labels_snapshot.csv`, `anchor_boxes_snapshot.csv`: exact reviewed labels.
- `experiment.mat`: per-frame final polygons and inlier correspondences,
  candidate evidence, thresholds and configuration.
- `visualizations\frame_*.jpg` and `demonstration.mp4`: held-out annotations
  (cyan reference, yellow baseline, green final). Playback is 3 fps for
  inspection, not the measured processing rate.

The report selects observed TP, printed-replica TN, FP and FN examples. If one
does not occur, it states that honestly. Discuss each observed failure with its
ranked candidate evidence. Anchor-win counts measure usage, **not** a causal
ablation; do not claim every anchor helps equally from wins alone.
